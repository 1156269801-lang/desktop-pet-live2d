# 小世界模式（桌宠第二形态）设计案

> 状态：**第一层已落地并通过端到端验证**（世界状态 + 桌面漫游 + 主进程接线）。
> 渲染层表现与小游戏尚未接入，见文末「下一步」。

## 1. 两种形态的分工

| | 第一形态：助手形态（现状） | 第二形态：小世界（本方案） |
|---|---|---|
| 窗口 | 大窗 870×1114，占屏幕一角 | 小方块 260×300，可满桌面移动 |
| 站位 | 站在固定位置，等你说话 | 自己爬、自己玩、自己找角度待着 |
| 目的 | 陪聊、直播搭子、语音助手 | 自娱自乐 + 轻养成（金币 / 道具 / 心情） |
| 交互 | 你主动发起 | 它主动发起，你偶尔插手 |
| 参考 | — | QQ 宠物 / 早期桌面宠物 |

两者**共用同一个 Live2D 渲染、同一个口型层、同一个记忆与人设**。
小世界不是另一个程序，是同一个角色换了一种「活法」。

## 2. 三层结构

```
┌─ 世界层  electron/pet-world.js ────────────────────────────┐
│  金币 / 背包 / 三项需求 / 道具表 / 小游戏结算                  │
│  纯逻辑：不碰 Electron、不碰文件、不碰网络                      │
│  存档挂在 state.json → state.games.world                     │
└────────────────────────────────────────────────────────────┘
                          ↕（主进程持有）
┌─ 漫游层  electron/roamer.js + electron/world-mode.js ───────┐
│  roamer：目标点选择、缓动移动、屏幕边界夹紧、待机计时           │
│  world-mode：进出模式、收小/还原窗口、出帧、暂停判定            │
│  同样纯逻辑：不直接 setBounds，只吐坐标                        │
└────────────────────────────────────────────────────────────┘
                          ↕（main.js 接线，30fps）
┌─ 渲染层  renderer/（下一步）───────────────────────────────┐
│  走路姿态、到点自娱自乐、气泡、心情表情、背包商店 UI            │
│  只挑「播什么」，时机由主进程给                                │
└────────────────────────────────────────────────────────────┘
```

**为什么主进程只发时机、内容交给渲染层**：动作名（`打招呼.motion3.json`）和表情名随模型变化，主进程不知道当前模型有哪些动作。渲染层手上有 `capabilities`，让它自己挑才不会出现「调用了不存在的动作」。

## 4. 关键设计决策（含踩过的坑）

**① 绝不做「全屏透明层」当桌面。**
`main.js` 里原有注释已经踩过：铺满屏幕的置顶窗口会让 Chromium 判定自己完全被遮挡，后台视频停止渲染（画面黑、声音还在）。所以漫游只能靠**移动一个小窗口**实现，不能靠在大画布里挪动精灵。

**② 30fps，且只在真变了才 setPosition / 发 IPC。**
Windows 上每帧 `setBounds` 会推高 DWM 负载。现在：位置没变不调 `setPosition`，走路状态没变不发 IPC。

**③ 三项需求必须各自计时。**
最初三个需求共用一条 `decayAt` 时间线，结果 satiety 攒到 12 分钟结算时把 mood 攒的 14 分钟一起清零了。改成 `timers.at = { satiety, mood, energy }` 各自推进。

**④ 体力地板必须低于小游戏消耗。**
地板原本定 8，而「戳泡泡」消耗 6 —— `energy` 永远不会低于 6，「体力不足收益减半」这条规则**永远触发不了**。地板改成 2。这类「两个常量互相挡死」的 bug，只有测试会抓出来。

**⑤ 掉落用浮点位置 + 离线封顶 + 地板值。**
- 内部坐标保留浮点，只在输出时取整。否则最后 1px 的位移每帧被四舍五入吃掉，宠物会卡在离目标 10px 处一直「走」。
- 离线最多算 6 小时，回来不会看到一个饿到 0 的宠物。
- 需求有地板（satiety 5 / mood 10 / energy 2），到底就停：**陪伴向，不惩罚**。

**⑥ 世界模式期间不写窗口几何存档。**
不然退出小世界后，第一形态的大窗口尺寸就被 260×300 覆盖了。`rememberWindowBounds()` 开头 `if (isWorldActive()) return`。

**⑦ 暂停优先级**（任何一个成立就立刻停下）：
窗口不可见 / 圆球模式 / 正在演出（showRunning）/ 用户刚拖过窗口（1.2s 内）/ 聊天窗·面板·控制台·设置窗打开。

## 5. 手感参数在哪调

```
electron/roamer.js        speed 155px/s · accel 900 · margin 16 · idle 2.6~7.8s · groundBias 0.55
electron/world-mode.js    WORLD_SIZE 260×300 · MIN_SIZE 220×240 · FRAME_MS 33
electron/pet-world.js     DECAY_MS（饥饿 12min / 心情 15min / 体力 10min）· OFFLINE_CAP 6h
                          NEED_FLOOR · ITEMS 价格与效果 · GAMES 收益系数
```

`groundBias` 是「像在地上爬」的关键：0.55 表示 55% 的目标点落在屏幕下 45% 的带状区域。

## 6. 下一步

1. **渲染层行走表现**（最影响观感）
   收到 `world-walk` 后：身体左右轻摆 + 上下小幅起伏（走 ParamBodyAngleZ / 头部微动），`facing` 决定朝向翻转。没有走路动作的模型也不会违和——**用位移 + 微摆伪装走路**，比硬套一个不匹配的动作自然。
2. **自娱自乐**（收到 `world-event: idle`）
   从 capabilities 里挑动作/表情组合，少量气泡台词（复用现有 `localLines` 规则池），受 `life-state` 的夜间 `maxSpeechCharacters` 约束。
3. **背包与商店面板**
   复用 `panel.html` 那套独立小窗，`pet:world-state` 拿数据，买 / 用 / 玩走三个 IPC。
4. **小游戏**
   第一个做「戳泡泡」：纯 canvas，结束上报 `{ gameId, score }` 到 `pet:world-play`，结算全在主进程（经济系统只有一份）。
5. **心情驱动外观**
   `moodTier()` 已经返回 `great / fine / low / poor`，接表情和动作频率即可。
